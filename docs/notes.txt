revision log
	2013-06-25 10:24pm, now selects word under cursor if there is no text selected
	2013-10-14, sublime text 3 version added on the st3 branch
	2026-07-27, rewritten for python 3 / ST4
		the old scrape of google's results page for "Did you mean" / "Showing results for"
		stopped working -- google removed that markup, so the regex never matched and the
		plugin silently did nothing. verified 0/5 matches on known misspellings.
		now uses the suggest endpoint w/ client=psy-ab, the one client that returns explicit
		spell-correction metadata: za = corrected, zb = what you typed. that flag is what
		makes silent replacement safe -- no flag, no change to your text.
		fallback accepts a top suggestion only if it reads as a respelling (same word count,
		small per-word edit distance, same first letter), which stops "receive" -> "received"
		and stops phrases being extended into a full search query.
		also: all cursors checked in one pass (replaced back to front), case preserved,
		leading/trailing whitespace preserved, runs off the UI thread.
		verified 39/39: 19 misspellings corrected, 20 correct phrases left alone.
		st2/st3 branches retired, everything on master. package control channel PR:
		https://github.com/sublimehq/package_control_channel/pull/9501
		(note: wbond/package_control_channel now redirects to sublimehq/)
	2026-07-27, tests/test_correct.py added, live corpus run w/ `python3 tests/test_correct.py`
		"battery terminalss" exposed a bug: a doubled trailing letter was rejected by the
		src.startswith(cand) guard, which was there to stop "receive" -> "received".
		both are a 1-char difference at the end, so the rule had to become asymmetric --
		candidate LONGER than what you typed = google completing you, reject;
		candidate SHORTER by a <=2 char tail w/ no space = you typed extra, accept.
		also added retry w/ backoff after the suite tripped the endpoint's 500s.
		44 cases pass: 19 misspellings, 18 correct-and-untouched, 5 offline, 2 case.
	2026-07-27, per-word fallback, tagged v2.0.0
		"additionassl microcontrollers" exposed a second gap: google's only suggestion for
		that phrase is an extension ("...are being"), so nothing phrase-level was acceptable,
		even though "additionassl" alone corrects to "additional" fine. some misspellings
		are simply invisible at phrase granularity.
		correct() now tries the phrase, then falls back to checking each word on its own.
		this forced a distinction between "google has no correction" and "google echoed the
		text back unchanged" -- both used to be None. the latter is now an AGREE sentinel
		that skips the per-word pass, so correct text isn't re-examined word by word.
		per-word pass skips words < 4 chars and non-alpha, keeps punctuation attached, and
		preserves spacing by splitting on a capturing whitespace pattern (a plain
		' '.join(src.split()) would collapse runs of spaces).
		cost: a phrase can now take up to N+1 requests, but only when the phrase-level
		check comes up empty. this makes the retry/backoff load-bearing rather than
		precautionary -- the per-session cache in the backlog would cut it down.
		50 cases pass. the 4 new correct multi-word phrases matter most: the per-word path
		is the riskiest thing here for silent replacement, so it needs pinning down that it
		leaves good text alone.

	testing note
		tests need network and take ~1 min w/ the 0.8s throttle. without the throttle the
		suggest endpoint 500s partway through a full run.
